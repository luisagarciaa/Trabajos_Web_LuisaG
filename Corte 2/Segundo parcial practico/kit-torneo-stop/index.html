Reglas del Torneo

  1. La letra del torneo se sortea al minuto cero y es la misma para todo el grupo. Todo el contenido que usted invente —nombres, respuestas, nombre del torneo— debe empezar por esa letra
  2. Las rondas son secuenciales: lo que construye en una es el insumo de la siguiente.
  3. Al final de cada ronda el profesor anuncia ¡STOP!: todos hacen commit con el formato ronda-NN: descripción. El historial de git es parte de la evaluación.
  4. Se permite consultar documentación oficial: MDN, react.dev, getbootstrap.com y la documentación de TypeScript.
  5. No se permiten asistentes de inteligencia artificial, código propio de proyectos anteriores ni plantillas descargadas.
  6. Todo se escribe durante el parcial, desde una carpeta vacía. Lo único que recibe es el kit del torneo.
  7. No se evalúa backend, bases de datos ni estado en React: este parcial cubre HTML, CSS, JavaScript y componentes con props.
  8. Cada estudiante tiene dos comodines PISTA (el profesor responde una duda puntual; cuesta el 10 % de esa ronda) y un comodín SALTO (usa el archivo de rescate del kit para continuar; esa ronda vale 0 pero la cadena no se rompe).
  9. Si una ronda no le funciona, documente en BITACORA.md qué intentó y qué error obtuvo: eso otorga puntaje parcial.
  10. La entrega se hace dentro del tiempo. Lo que llegue después no se evalúa.
